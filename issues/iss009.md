# Zadanie 009 — Komentarz z konsoli i ocena JSON

**Typ:** `User Story` | **Stan:** `New` | **Zakres:** opcjonalne TUI

**Warunek startu:** zakończone etapy 1–8 oraz odtworzona i rozpoznawana
przez Spec Kit specyfikacja stanu istniejącego z [zadania 010](iss010.md).

## Opis

Jako użytkownik chcę wpisać identyfikator sklepu i komentarz w konsoli,
a następnie otrzymać ocenę w JSON zgodną z wynikiem formularza WWW.

## Zadanie

- Utwórz osobną specyfikację `console-triage`, plan i zadania w Spec Kit.
  Nie nadpisuj specyfikacji stanu istniejącego.
- Po doprecyzowaniu i analizie dodaj `python -m triage.console`
  bez nowych pakietów. To moduł do implementacji, nie polecenie startera.
- W jednym uruchomieniu pobierz jeden `store_id` i jeden komentarz,
  po jednym wierszu na każde pole.
- Użyj tej samej usługi i walidacji co WWW, bez duplikowania klasyfikacji
  i bez wymagania uruchomionego serwera HTTP.

## Kryteria akceptacji

- Sukces: jeden obiekt JSON na `stdout`, kod `0`; pytania na `stderr`.
  Pola i wartości są zgodne z aktualnym `POST /api/triage`, łącznie
  z `actionability`, stanami `no_action` i `manual_review` oraz szkicem `null`.
- Błąd wejścia, konfiguracji lub dostawcy: jawny komunikat na `stderr`,
  pusty `stdout`, kod `1`. Nie ma starego wyniku ani pozornego sukcesu.
- EOF/przerwanie: brak JSON, kod `2`; niedokończone wejście nie trafia
  do klasyfikacji.
- Obowiązuje maskowanie z briefu, tryby `demo`/`live` i brak
  automatycznego przełączenia trybu. Nie zapisuj historii komentarzy.
- Kontrakt API i raport ewaluacji pozostają bez zmian; szkic nie jest
  wysyłany do systemu zgłoszeniowego.
- Niewykonane rozszerzenie nie blokuje rdzenia.

## Jak sprawdzić

Porównaj całe obiekty JSON konsoli i API dla tego samego wejścia
i kontrolowanej odpowiedzi klasyfikatora. Sprawdź problem, pochwałę,
niejasną sprawę, puste wejście, tekst >4000 znaków, błędny sklep,
wymagane formaty PII, błąd dostawcy oraz EOF/przerwanie.
Potwierdź kanały wyjściowe i kody `0`/`1`/`2`, także przy przekierowaniu
`stdout` do pliku. W `live` nie porównuj dosłownie swobodnego uzasadnienia
z niezależnych wywołań modelu. Sam plan lub PASS pluginu nie potwierdza
ukończenia funkcji.
